 نظام إدارة التدريب الميداني (COOP)

**مشروع تطبيقي لمقرر برمجة الاعمال المتقدمة**

---

## 1. نبذة عن المشروع

تطبيق مكتبي متكامل بلغة **Java (واجهات Swing)** يعتمد على قاعدة بيانات علائقية محلية من نوع **Apache Derby (Embedded Mode)** للربط عبر **JDBC**. يحل النظام مشكلة حفظ بيانات التدريب الميداني لطلاب الكلية في ملفات إكسل منفصلة، حيث يوفر:
1. واجهة مستخدم رسومية حديثة باللغة العربية (RTL).
2. استيراداً مباشراً وفحصاً متقدماً لملفات **Excel (`.xlsx`, `.xls`)** وملفات **CSV** دون الحاجة لتحويل مسبق.
3. كشف القيم المتشابهة واقتراح توحيدها للمستخدم لمنع تشتت البيانات المرجعية.
4. عمليات الإدارة الكاملة للطلاب (إضافة، تعديل، حذف، بحث جزئي، وتصفية مركبة).
5. إحصائيات بيانية ملونة ورسوماً مرسومة باستخدام Java `Graphics2D`.
6. إدارة وتأمين البيانات المرجعية للتخصصات والمرشدين وجهات التدريب.

---

## 2. متطلبات التشغيل والبيئة (Prerequisites)

- **بيئة التطوير المدعومة:** NetBeans IDE (أي إصدار من NetBeans 8.2 وحتى Apache NetBeans 12 إلى 24).
- **إصدار Java:** Java SE (يدعم Java 8 و 11 LTS و 17 LTS و 21 و 25).
- **المكتبات الخارجية المضمنة في مجلد `lib/`:**
  - `derby.jar` & `derbytools.jar` (Apache Derby Embedded).
  - `poi.jar`, `poi-ooxml.jar`, `poi-ooxml-lite.jar` (Apache POI لمعالجة Excel).
  - `xmlbeans.jar`, `commons-collections4.jar`, `commons-io.jar`, `commons-compress.jar`.
  - `log4j-api.jar`, `log4j-core.jar`.
  - `jsvg.jar` (محرك معالجة ورسم ملفات المتجهات SVG وعرض شعار الجامعة).
  - **ملاحظة:** جميع المكتبات متوفرة محلياً داخل مجلد `lib/`، ولا يتطلب تشغيل المشروع أي اتصال بالإنترنت.

---

## 3. طريقة فتح وتشغيل المشروع في NetBeans IDE

1. افتح برنامج **NetBeans IDE**.
2. من القائمة العلوية، اختر: `File -> Open Project`.
3. انتقل إلى المجلد: `COOP_JAVA_PROJECT` واضغط **Open Project** (سيظهر بجانبه أيقونة فنجان القهوة كمشروع Java Ant قياسي جاهز).
4. اضغط على زر **Run Project (F6)** أو انقر بزر الفأرة الأيمن على اسم المشروع واختر **Run**.
5. ستفتح الواجهة الرسومية العربية مباشرة وتبدأ قاعدة البيانات تلقائياً.

---

## 4. طريقة التشغيل عبر سطر الأوامر (Terminal)

إذا أردت ترجمة وتشغيل المشروع مباشرة من سطر الأوامر:

### أ) الترجمة (Compile):
```bash
mkdir -p build/classes
javac -encoding UTF-8 -cp "lib/*:src" -d build/classes src/coop/model/*.java src/coop/dao/*.java src/coop/exception/*.java src/coop/util/*.java src/coop/service/*.java src/coop/ui/components/*.java src/coop/ui/*.java src/coop/Main.java
```

### ب) التشغيل (Run):
```bash
java -Dfile.encoding=UTF-8 -cp "lib/*:build/classes" coop.Main
```

### ج) تشغيل الاختبارات البرمجية الشاملة:
```bash
# اختبارات قاعدة البيانات
java -Dfile.encoding=UTF-8 -cp "lib/*:build/classes" test.DBConnectionTest

# اختبارات Model و DAO
java -Dfile.encoding=UTF-8 -cp "lib/*:build/classes" test.ModelAndDAOTest

# اختبارات قراءة Excel و CSV والاستيراد
java -Dfile.encoding=UTF-8 -cp "lib/*:build/classes" test.ExcelAndImportTest

# اختبارات طبقة الخدمات والتحقق
java -Dfile.encoding=UTF-8 -cp "lib/*:build/classes" test.ServiceLayerTest
```

## 5. دليل استخدام ميزة استيراد البيانات (Excel & CSV)

1. من القائمة العلوية للتطبيق، اضغط على تبويب **"استيراد البيانات"**.
2. اضغط على **"استعراض الملفات..."** واختر ملف Excel أو CSV (يمكنك تجربة ملف النموذج المرفق `بيانات التدريب الميداني.xlsx`).
3. إذا كان ملف Excel يحتوي أكثر من ورقة، اختر الورقة المطلوبة من القائمة المنسدلة.
4. اضغط على زر **"معاينة وفحص البيانات"**:
   - سيتعرف النظام تلقائياً على الأعمدة (الاسم، الشطر، التخصص، المرشد، جهة التدريب).
   - سيعرض إجمالي الصفوف، السجلات الصالحة، والسجلات الناقصة أو المكررة بلون مميز.
5. في حال وجود أسماء جهات أو مرشدين مكتوبة بصيغ مختلفة (مثل: "الغرفة التجارية" و"الغرفه التجاريه")، سيتفعل زر **"مراجعة توحيد الأسماء المتشابهة"** بلون برتقالي:
   - اضغط عليه لمراجعة الاقتراحات واختيار ما توافق على توحيده بوضع علامة صح.
6. حدد السجلات التي ترغب باستيرادها، ثم اضغط على زر **"اعتماد وبدء الاستيراد النهائي"**.
7. تُنفذ العملية كمعاملة آمنة (Transaction)، ويظهر تقرير ختامي يوضح عدد السجلات المستوردة والمراجع الجديدة.

## 6. الهيكل المعماري للحزم البرمجية (Packages Structure)

- **`coop.model`**: كلاسات الكيانات وتطبيق مبادئ OOP (الوراثة والتغليف: `Person`, `Student`, `Advisor`, `Organization`, `Specialization`).
- **`coop.dao`**: طبقة الوصول لقاعدة البيانات عبر JDBC والواجهة العامة (`DBConnection`, `Dao<T>`, `StudentDAO`, `AdvisorDAO`, `OrganizationDAO`, `SpecializationDAO`).
- **`coop.service`**: منطق الأعمال والتحقق وتنسيق المعاملات (`StudentService`, `ReferenceDataService`, `ImportService`, `DataNormalizationService`).
- **`coop.util`**: قراءة الملفات والأدوات المساعدة (`ExcelReader`, `CSVReader`, `ValidationUtil`).
- **`coop.exception`**: الاستثناءات المخصصة (`DataAccessException`, `ValidationException`).
- **`coop.ui`**: شاشات الواجهة الرسومية وتوزيع المكونات باللغة العربية (`MainFrame`, `DashboardPanel`, `StudentPanel`, `StudentFormDialog`, `ImportDataPanel`, `StatisticsPanel`, `ReferenceDataPanel`).

## 7. دليل الأسئلة المتوقعة في المناقشة الأكاديمية (Oral Defense Q&A)

إليك أهم الأسئلة التي يطرحها عادةً أساتذة مقرر MIS412 وإجاباتها النموذجية من واقع كود المشروع:

### س1: لماذا استخدمنا قاعدة بيانات علائقية بدلاً من الاكتفاء بملف الإكسل؟
**ج:** ملف الإكسل مسطح (Flat File) يؤدي لتكرار النصوص (Redundancy) وأخطاء التهجئة وصعوبة الاستعلام والتحديث. قاعدة البيانات العلائقية تُقسّم البيانات إلى جداول مرتبطة بمفاتيح، مما يمنع التكرار ويضمن تكامل البيانات (Integrity) ويسهل البحث والتصفية واستخراج الإحصائيات.

### س2: كيف حقق تصميم الجداول الصيغة الطبيعية الثالثة (3NF)؟
**ج:** 
- **1NF:** جميع القيم ذرية (Atomic) بدون حقول مكررة.
- **2NF:** جميع الحقول تعتمد بالكامل على المفتاح الأساسي للجدول.
- **3NF:** تم التخلص من الاعتمادية المتعدية (Transitive Dependency)؛ حيث فُصلت أسماء التخصصات والمرشدين وجهات التدريب في جداول مرجعية مستقلة، وحُفظت في جدول الطالب كمفاتيح أجنبية أرقاماً فقط.

### س3: ما وظيفة نمط DAO (Data Access Object)؟
**ج:** هو نمط تصميم يفصل منطق التعامل مع قاعدة البيانات واستعلامات الـ SQL عن واجهات المستخدم ومنطق الأعمال. فائدته أنه لو قمنا بتغيير نوع قاعدة البيانات مستقبلاً، سنعدل فقط كلاسات الـ DAO دون لمس الواجهات الرسومية.

### س4: أين تم تطبيق مفاهيم البرمجة الكائنية (OOP) في المشروع؟
**ج:**
- **التغليف (Encapsulation):** جميع الحقول في كلاسات الـ Model معرفة كـ `private` ويتم الوصول إليها عبر `getters` و `setters` مع التحقق من صحتها.
- **الوراثة (Inheritance):** يرث كل من `Student` و `Advisor` من الكلاس الأساسي المجرد `Person` الذي يجمع (المعرف والاسم).
- **التعددية والتجريد (Polymorphism & Abstraction):** استخدام الواجهة العامة `Dao<T>` التي ترث منها وتطبقها جميع كلاسات الوصول للبيانات.

### س5: لماذا استخدمنا `PreparedStatement` بدلاً من `Statement` العادي؟
**ج:**
1. **الأمان:** لحماية التطبيق من هجمات حقن الـ SQL (SQL Injection).
2. **التعامل مع النصوص:** معالجة علامات الاقتباس والمسافات والأحرف العربية دون تشويه أو خطأ في جملة الاستعلام.
3. **الأداء:** تجميع الاستعلام مسبقاً في المحرك وإعادة استخدامه.

### س6: كيف تضمنون عدم تجمد واجهة المستخدم (GUI Freezing) أثناء قراءة الملفات الكبيرة أو الاستيراد؟
**ج:** نستخدم كلاس `SwingWorker` لتشغيل العمليات الثقيلة (قراءة Excel واستعلامات القاعدة) في خيط عمل خلفي (Background Thread)، مع إبقاء خيط واجهة المستخدم (Event Dispatch Thread) حراً ومستجيباً، وعرض شريط تحميل (ProgressBar) للمستخدم.

### س7: كيف تعمل ميزة المعاملات (JDBC Transactions) في الاستيراد؟
**ج:** نستخدم `connection.setAutoCommit(false);` قبل بدء إدخال سجلات الملف. إذا استوردت جميع السجلات بنجاح يتم استدعاء `connection.commit();`. أما إذا حدث خطأ غير متوقع في أي سجل، يُنفذ فوراً `connection.rollback();`، مما يضمن عدم ترك قاعدة البيانات في حالة جزئية غير متسقة.
